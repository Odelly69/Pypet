# Pypet Academy — Cumulative Learning Progression

Every lesson is cumulative. A lesson may introduce one new concept, but its exercises must deliberately reuse skills from earlier lessons. The learner should continuously build one working mental model and one growing portfolio rather than complete disconnected worksheets.

## Lesson contract

Every lesson uses this sequence:

1. **Learn** — introduce the new concept and explicitly recall the prerequisite concepts.
2. **See** — demonstrate the new concept inside code the learner has already built.
3. **Write** — learner edits or extends the previous lesson's working program; new code is not a disconnected toy unless the prerequisite is intentionally isolated.
4. **Run** — execute the updated program.
5. **Inspect** — observe output, state, graphics, files, or pet/world behavior.
6. **Debug** — diagnose at least one realistic mistake or failed requirement.
7. **Practice** — guided extension using the same project.
8. **Challenge** — independent extension combining the new concept with earlier concepts.
9. **Apply** — use the skill in the Pypet World, pet care, game, GUI, graphics, automation, or job-style project as appropriate.
10. **Reflect** — explain what changed and why it works.
11. **Master** — pass the competency check; only then is the lesson marked mastered.

## Dependency rules

- Lesson N has explicit prerequisites from earlier lessons.
- A learner can review/retry prerequisites, but cannot permanently bypass required mastery.
- New lessons must reference the learner's existing project state and prior concepts.
- Assessments mix the current skill with previously learned skills.
- A failed assessment returns the learner to targeted review, not a punishment loop.
- Mastery is retained and revisited through spaced cumulative challenges.
- Each module ends with an integrated project using the module's skills plus earlier modules.
- Each major level ends with a larger capstone that remains the basis for the next level.
- The final job-readiness capstone combines the entire curriculum.

## Progression architecture

### Foundations

Variables → types → strings/numbers/booleans → input/output → operators → conditionals → loops → functions.

Each lesson modifies the same introductory pet/World program. For example, loops operate on the data and functions created earlier instead of introducing unrelated examples.

### Core Python

Functions → collections → iteration → comprehensions → errors → files → modules/packages.

The learner progressively turns the introductory program into a reusable application with persistent data and multiple modules.

### Standard library and professional Python

The growing application gains paths, JSON/CSV persistence, dates, randomness, regular expressions, collections/itertools/functools, logging, CLI behavior, typing, dataclasses, testing, debugging, packaging, and dependency management.

### Applications

HTTP/APIs → JSON → SQLite/SQL → data processing → automation → concurrency/asyncio → security fundamentals.

Each lesson extends the same application into a professional data/service workflow.

### GUI and games

Tkinter event handling and widgets build a usable desktop tool. Pygame then builds a game from the same programming foundations: game loop → input → sprites → collision → state → sound → animation → architecture.

### Graphics

Screen coordinates → coordinate systems → resolution independence → scaling → aspect ratios → transforms/vectors → sprites → animation → camera → 3D coordinates → meshes → lighting/material concepts → 3D animation → optimization.

Coordinate lessons must explicitly reuse earlier variables, functions, conditionals and loops. Graphics projects must work at multiple resolutions.

### Mastery/job readiness

Architecture → maintainability → documentation → code review → tests → debugging → Git/GitHub workflow → portfolio → technical writing → interview problems → project presentation → workplace communication → final capstone.

The final capstone must require the learner to design, build, test, debug, document, version, present, and explain a complete project using previously mastered skills.

## Pet/world connection

The learner's progress is the pet's learning progress. New curriculum mastery unlocks meaningful World capabilities. Examples:

- variables/conditionals → basic pet-state logic
- loops/functions → repeated pet behaviors
- collections → inventory and pet data
- files/JSON → persistent pet/world records
- Tkinter → usable tools
- Pygame → interactive game systems
- coordinates → precise World interactions
- animation → pet movement
- 3D graphics → World/asset systems
- APIs/data → advanced World services
- testing/debugging → reliable game systems
- job-readiness capstone → complete portfolio-quality project

The game should never claim that a lesson is mastered merely because the learner viewed it. Mastery requires completing the cumulative hands-on work.
